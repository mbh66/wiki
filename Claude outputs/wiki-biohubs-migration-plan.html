Phase 1

Rename the wiki repo and folder

GitHub
Rename repo mbh66/biohubs → mbh66/wiki
Settings → General → Repository name. GitHub auto-redirects the old URL, so existing links and the upstream remote won't break immediately.
Local
Rename folder /Documents/biohubs → /Documents/wiki
Close Obsidian first so it doesn't hold file locks.
mv ~/Documents/biohubs ~/Documents/wiki
Update the git remote origin URL
cd ~/Documents/wiki git remote set-url origin https://github.com/mbh66/wiki.git
Reopen the vault in Obsidian from the new path
Open Obsidian → "Open another vault" → Browse → select /Documents/wiki. All vault settings in .obsidian/ travel with the folder, so nothing else changes.
Quartz config
No changes needed
baseUrl stays wiki.bioconomy.earth. The CNAME file stays as is. The GitHub Actions workflow stays as is. The only thing that changed is where the folder lives on your machine and what the repo is called on GitHub.
Verify
Push a small commit from the renamed folder and confirm the GitHub Actions build runs
cd ~/Documents/wiki git add -A && git commit -m "test: verify build after repo rename" git push origin v5
Confirm wiki.bioconomy.earth still loads
Check GitHub → repo Settings → Pages to verify the custom domain is still configured. The rename preserves Pages settings, but verify.
Sequence note

Complete Phase 1 and verify the wiki still builds before touching anything else. The rename frees up the name "biohubs" on GitHub for the new repo.

Phase 2

Create the BioHubs site

GitHub
Create new repo mbh66/biohubs on GitHub
Empty repo, no README. This reclaims the name freed by the rename in Phase 1.
Local setup
Initialize a fresh Quartz v5 project for biohubs
cd ~/Documents npx @jackyzha0/create-quartz biohubs cd biohubs git remote add origin https://github.com/mbh66/biohubs.git
Create the CNAME file
echo "biohubs.bioconomy.earth" > CNAME
Edit quartz.config.yaml
Set baseUrl: biohubs.bioconomy.earth. Copy the theme colors from the wiki config if you want visual consistency, or set new ones for biohubs. Enable the cname plugin.
Content structure
Create the biohub content folders
mkdir -p content/at12-vog content/at12-overberg
Create content/index.md as the biohubs landing page
This becomes biohubs.bioconomy.earth/. An index listing all biohubs, with links to each.
Create content/at12-vog/index.md and content/at12-overberg/index.md
These become biohubs.bioconomy.earth/at12-vog and .../at12-overberg. Each biohub folder will hold its own pages, and the index serves as the biohub's landing page.
GitHub Actions
Copy the deploy workflow from the wiki repo
Copy .github/workflows/deploy.yml from /Documents/wiki into the new biohubs project. No changes needed; the workflow is generic Quartz.
Governance optional now
Add a CODEOWNERS file for per-biohub review gates
# .github/CODEOWNERS # Each biohub folder requires approval from its team /content/at12-vog/ @mbh66 /content/at12-overberg/ @mbh66
Enable branch protection on the default branch
Settings → Branches → Add rule for v5. Require pull request reviews, require CODEOWNERS review. This prevents direct pushes to other teams' folders.
Obsidian
Open /Documents/biohubs as a second vault in Obsidian
You'll have two vaults: "wiki" and "biohubs". Wikilinks within each vault resolve normally. Cross-wiki links (biohub page linking to a wiki concept) won't resolve in Obsidian but will need to be full URLs in the published site.
Deploy
Push to GitHub and enable Pages
cd ~/Documents/biohubs git add -A git commit -m "initial biohubs site with at12-vog and at12-overberg" git push -u origin v5
Enable GitHub Pages
Settings → Pages → Source: GitHub Actions. The custom domain will be set in the DNS phase.
Phase 3

DNS and domain configuration

At your DNS provider (for bioconomy.earth)
Verify wiki.bioconomy.earth CNAME still points correctly
Should be a CNAME to mbh66.github.io. The repo rename doesn't affect this because GitHub Pages resolves by the CNAME file inside the repo, not the repo name.
Add CNAME record: biohubs.bioconomy.earth → mbh66.github.io
GitHub Pages custom domain
In the mbh66/biohubs repo, go to Settings → Pages → Custom domain
Enter biohubs.bioconomy.earth. GitHub will verify the DNS and provision a TLS certificate. This can take a few minutes. Check "Enforce HTTPS".
Verify both sites load
wiki.bioconomy.earth serves the wiki. biohubs.bioconomy.earth serves the biohubs landing. biohubs.bioconomy.earth/at12-vog loads the Valley of Grace biohub.
GitHub Pages constraint

GitHub allows one custom domain per repo. Two repos under the same GitHub account can each have their own custom subdomain of the same apex domain (wiki.bioconomy.earth and biohubs.bioconomy.earth) without conflict. Each repo's CNAME file tells GitHub which domain maps to which repo.

Estimated time: 30 to 45 minutes if DNS propagation is fast. Phase 1 is 5 minutes of actual work. Phase 2 is 15 to 20 minutes. Phase 3 depends on your DNS provider's propagation speed.

Rollback: If anything breaks the wiki, renaming the repo back to "biohubs" and the folder back to /Documents/biohubs restores the original state completely. The new biohubs repo is independent and can be deleted without affecting the wiki.
